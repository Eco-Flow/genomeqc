## v1.0.0 - [12 August 2026]

### `Added`

- Added FCS-GX contamination stats to the tree summary plot ([#265](https://github.com/nf-core/genomeqc/issues/265)): each genome's percentage of the assembly flagged as foreign contamination is now shown as a pie chart (non-contaminant/contaminant, coloured to match the BUSCO panel) in the conventional layout, or a Good (≥99.5% non-contaminant) / Warn (98-99.5%) / Poor (<98%) traffic-light ring in the circular layout (`--tree_style circular`), reusing the existing quality-scoring machinery (`--quality_preset`/`--quality_thresholds`, new `fcs_noncontam` metric). Only shown when decontamination was run (`--gxdb`/`--gxdb_manifest`). Added a new local module (`fcsgx_report_2_table`, mirroring the existing `te_tbl_2_table` pattern) to parse each species' `*.fcs_gx_report.txt` header into a combined per-species contamination table for the tree plot.
- Added nf-test pipeline-level coverage for the decontamination workflow (`tests/decon.nf.test`) and the existing `test_gca` profile (`tests/gca.nf.test`), previously exercised by CI only indirectly via module/subworkflow-level tests, not as a full pipeline run.
- Split `busco/<species_name>/` into `busco/genome/<species_name>/` and `busco/protein/<species_name>/`, and `validated_gff/<species_name>/` into `validated_gff/agat/<species_name>/` and `validated_gff/gffread/<species_name>/`: both previously published genome-mode and protein-mode (or AGAT- and GffRead-validated) outputs under one shared path, so a genome+annotation run silently overwrote one mode's files with the other's whenever both ran for the same species. Merged `orthofinder_v2`/`orthofinder_v3` under `orthofinder/v2`/`orthofinder/v3` for the same reason. Renamed the underlying `BUSCO_BUSCO` module aliases to `BUSCO_GENOME`/`BUSCO_PROTEIN` to match.
- Fixed a stale filename reference in `bin/shiny_app.R` left over from the `ORTHOLOGOUS_CHROMOSOMES`→`ORTHO_SEQ_COUNT` rename: it was still checking for `species_orthologous_chromosomes_output.tsv`, which no longer exists, so the interactive Shiny app's ortho-seqs panel silently never loaded. Also corrected two pre-existing `fsc_gx_report.txt`/`fsc_adaptor_report.txt` typos in `docs/output.md` (should read `fcs_...`) and broadened `--skip_plots_genome_anno`/`--skip_plots_genome_only`'s schema validation patterns, which predated the BUSCO-pie-split and TE-panel work and so rejected several stat keys (`busco_gen_plot`, `busco_prot_plot`, `te_plot`) that are valid today.
- Fixed the circular tree layout's rings (`--tree_style circular`) rendering wildly uneven thicknesses - the outermost ring could be several times wider than every other ring, regardless of how many rings were shown. Root cause: `ggtreeExtra::geom_fruit()` draws each ring as a tile far wider than its intended thickness, staggered by `offset` and relying on the _next_ ring being drawn on top to visually clip it down to size - the last ring has nothing after it to clip its trailing edge, so it alone rendered at its full, unclipped width. Separately, `geom_fruit()`'s very first call on a fresh tree also allocates a one-off, disproportionate slice of radius that a fully transparent "primer" ring now absorbs. Rings now calibrate their own width at runtime by measuring the actual stagger `offset` produces on the tree in hand, so every ring - including the last - renders the same true thickness. Verified via direct inspection of the rendered plot's layer geometry (not just visual inspection) across 2, 5, and 8-ring configurations.
- Fixed `--show_ring_values`' printed numbers landing one ring inward from the ring they describe (e.g. N50's value appearing over the Genome size ring instead of N50's own), a knock-on of the primer-ring fix above: the primer added an extra rendered layer that the value-label placement logic wasn't skipping. Confirmed by comparing each label's plotted position against its ring's actual boundaries directly, not just visually.
- Fixed the conventional (non-circular) tree layout's **TE** column title rendering below its panel instead of above it, out of line with every other column's title. It reused the two-line titles' `vjust=-5`, which does not translate to a single-line title like "TE" - repinned to match `N50 (Mb)`'s single-line calibration (`vjust=-0.4`) instead.
- Fixed the FCS panel/ring rendering against the wrong species whenever FCS-GX only ran for some of the tree's tips - which is the normal case, since FCS-GX only runs for samples with a `taxid` set in the samplesheet (a pre-existing, documented, per-sample opt-in, unrelated to this change). `load_fcs()`/`load_te()` numbered each present species sequentially (1, 2, 3...) rather than by that species' real position among all tips, so a species' pie could silently land on a _different_ tip's row whenever the taxid-bearing species wasn't first in tip order. Fixed by deriving each row's position directly from its match against the full tip list, and dropping (rather than mis-numbering) any row that doesn't match one.
- Fixed a related, more serious issue in the circular layout specifically: the FCS ring (or any ring built from partial per-species data) didn't just misplace a single species' grade, it silently copied that _one_ species' Good/Warn/Poor colour onto every other tip in the ring, via R's vector recycling when a short (partial) values vector was assigned across all tips' rows - fabricating a contamination grade for species that had no FCS data at all. Species without data now correctly render with no colour (grey, matching the ring's existing "no data" style) instead of a copied, incorrect one.
- Fixed SVG export failing in the interactive Shiny app (PNG export was unaffected): `ggsave(..., device = "svg")` requires the `svglite` R package, which isn't installed in the app's container. Switched to base R's `svg()` device directly, matching `plot_tree_summary.R`'s own SVG export, which needs no additional dependency.
- Fixed CI: `.github/actions/nf-test/action.yml` never set `NFT_PROFILE`, silently making pipeline-level tests' `cleanup { docker system prune }` block dead code (the `System.getenv("NFT_PROFILE")` check was always null). Also increased nf-test's shard count (7→10) to spread container-pulling tests across more runners, reducing the disk pressure that was causing intermittent `no space left on device` failures.
- Fixed `-profile test`'s RepeatModeler/RepeatMasker snapshot being unreproducible between runs: RepeatModeler seeds its random sampling from wall-clock time (`my $seed = time` in its own source) unless `-srand` is passed, so its de novo repeat library - and everything downstream that depends on it - differed on every run. Pinned `-srand 1` and forced single-threaded execution (RepeatModeler can still resolve equally-scoring ties differently depending on thread completion order even with a fixed seed) for the test profile. Verified `.masked`/`.out` (the actual masked-genome output) are now byte-identical across repeated runs; the `.tbl` summary-statistics file and downstream `te_table*.tsv` are excluded from snapshot content checks instead, since they remained unreproducible for reasons not yet root-caused.
- Fixed `--RM_download_db true` never actually downloading a DFAM partition: `FASTA_ANNOTATE_TE` unconditionally reassigned its own `ch_rm_db` input to `channel.empty()` right after taking it as a parameter, discarding the correctly-built download channel before `RM_DOWNLOAD_DB` could ever see it, regardless of the setting. Only affected users who don't pre-stage a library via `--famdb_library`. Added a stub-mode regression test (`sarscov2_genome-repeatmasker-download-stub`) exercising the download path with no pre-staged library, since the existing TE subworkflow tests only covered the pre-staged path.
- Corrected two stale/inaccurate doc statements found while writing this fix: `docs/output.md`'s TE annotation section said the DFAM library is "downloaded automatically unless `--RM_download_db false`" (backwards - it's off by default and must be opted into) and that clustering uses "CAT + CD-HIT-EST" (the actual default, and only option available before `--te_clusterer` existed, is MMseqs2 `easy-linclust`). Also added a note to `docs/circular_quality_scoring.md`, an internal design-proposal doc, flagging that its example threshold numbers predate the per-clade preset system and no longer match what's shipped, so it isn't mistaken for current documentation.
- Fixed `-profile conda` failing outright for `REPEATMODELER_REPEATMODELER`: an earlier bulk module update had deleted the module's `environment.yml`, `meta.yml`, and its own nf-test coverage, while `main.nf` still references `environment.yml` for its conda directive. Restored all three from upstream nf-core/modules (`nf-core modules install --force`), keeping the pipeline's existing container-version patch (RepeatModeler 2.0.7), and regenerated the patch record (`nf-core modules patch`) so it reflects only the real customization rather than the file deletions. Also repinned the restored `environment.yml`'s `repeatmodeler=2.0.5` to `2.0.7` to match what the docker/singularity containers already use - the same class of conda/container version drift already fixed for `orthologous_chromosomes`/`buscos_seqs`/`excel_report`/`html_report`, verified against bioconda's actual package listing before pinning.
- Excluded `SHINY_APP_GENOME`'s `cat` version from `tests/gca.nf.test`'s software-versions snapshot, completing the fix already applied to its `SHINY_APP_GENOME_ANNO` sibling: conda-forge's `linux-64` channel has no `coreutils=8.32` build (the version the docker/singularity base image ships), so the two profiles can never agree on it.

## v0.0.1 (dev) - [15 June 2026]

Initial pre-release of nf-core/genomeqc, created with the [nf-core](https://nf-co.re/) template.

This is the first release of the pipeline, which compares the quality of multiple genomes and their annotations. The pipeline runs in two modes depending on the inputs provided: **Genome only** (FASTA files) and **Genome and Annotation** (FASTA plus GTF/GFF files).

### `Added`

- Added `--te_clusterer` parameter to select the repeat library clustering tool used before RepeatMasker. Accepts `linclust` (default, MMseqs2 `easy-linclust`, linear time), `mmseqs` (MMseqs2 `easy-cluster`), or `cdhit` (CD-HIT-EST).
- Added `--te_cluster_identity` parameter (default `0.8`) to set the sequence identity threshold for repeat library clustering, applied across all three tools.
- Added `--te_cluster_coverage` parameter (default `0.8`) to set the alignment coverage threshold for repeat library clustering, applied across all three tools.
- Added `--repeatmasker_speed` parameter to control RepeatMasker sensitivity: `qq` (rush, default), `q` (quick), or `default` (most sensitive).
- Added `meta.yml` for all local modules (`modules/local/*`), and nf-test coverage (`tests/main.nf.test`) for a first batch of them, following nf-core module conventions.
- Changed the tree plot's TE composition panel from a pie chart to a 100%-stacked horizontal bar (colours left-to-right in the same order as the legend), matching the style already used for genome size and N50. Applies to both the static PDF/SVG and the interactive Shiny app.
- Added a `-profile test_gca` test dataset ([#202](https://github.com/nf-core/genomeqc/issues/202)) using GenBank (`GCA_`) accessions instead of RefSeq (`GCF_`), so the pipeline's NCBI-download path is covered for both accession namespaces, not just RefSeq.

- Fixed `--te_clusterer`'s schema description labelling `mmseqs` as the default when the actual default (both the schema's own `default` field and `nextflow.config`) is `linclust`.
- Fixed CI: the `decontamination` subworkflow test always failed under `-profile conda`, since `FCS_FCSADAPTOR` has no conda package and deliberately errors out under `-profile conda`/`mamba`. ## v0.0.1 (dev) - [12 June 2026]

Initial pre-release of nf-core/genomeqc, created with the [nf-core](https://nf-co.re/) template.

This is the first release of the pipeline, which compares the quality of multiple genomes and their annotations. The pipeline runs in two modes depending on the inputs provided: **Genome only** (FASTA files) and **Genome and Annotation** (FASTA plus GTF/GFF files).

### `Added`

- Input genomes and annotations from local files or NCBI accessions, downloaded with [NCBI genome download](https://github.com/kblin/ncbi-genome-download).
- Genome completeness assessment with [BUSCO](https://busco.ezlab.org/), including a **BUSCO Ideogram** plotting the location of markers on the assembly.
- Read-based genome completeness evaluation with [Merqury](https://github.com/marbl/merqury) (optional).
- Telomeric repeat identification and visualisation with [tidk](https://github.com/tolkit/telomeric-identifier) (optional).
- Assembly contiguity and integrity statistics (N50, N90, GC%, number of sequences) with [QUAST](https://github.com/ablab/quast).
- Contamination screening with [FCS-GX](https://github.com/ncbi/fcs/wiki/FCS-GX-quickstart), [FCS-adaptor](https://github.com/ncbi/fcs/wiki/FCS-adaptor-quickstart), and [Tiara](https://ibe-uw.github.io/tiara/).
- Annotation statistics (number of genes, features, lengths) with [AGAT](https://agat.readthedocs.io/en/latest/), and a **Gene Overlaps** analysis counting overlapping genes.
- Extraction of the longest protein isoform with [GffRead](https://github.com/gpertea/gffread).
- Orthologous gene inference with [OrthoFinder](https://github.com/davidemms/OrthoFinder) (v3).
- BUSCO marker-based and orthology-based phylogenetic **Tree Summary** plots combining assembly and annotation summary statistics.
- An executable Shiny app for interactively adjusting the tree plot and summary statistics, with PNG/SVG export.
- HTML and Excel summary reports.
- Aggregated quality-control report with [MultiQC](http://multiqc.info).
- New `--tree_style` option for the **Tree Summary** plot: `roundrect` (rounded branches, new default), `ellipse` (curved branches with node points), `rectangular` (legacy look with dotted leader lines), and `circular` (fan tree with the summary statistics drawn as concentric coloured rings and a numbered species key). Selectable in the Shiny app.
- New `--circular_rings` option controlling which stats appear as rings in the circular layout (any of `ch_plot`, `len_plot`, `n50_plot`, `gene_plot`, `busco_gen_plot`, `busco_prot_plot`, `nseqs_plot`, `ortho_plot`, or `all`). The static pipeline figure defaults to a curated assembly/annotation-quality set (sequence number, N50, genome BUSCO, protein BUSCO), while the Shiny app shows every non-skipped stat.
- Circular layout: the Good/Warn/Poor key now lists the per-metric thresholds (e.g. `BUSCO genome: 95+ / 90+ / <90`), read from whichever `--quality_preset` or custom thresholds are in force.
- New `--quality_thresholds` option to override individual `--quality_preset` cut-offs from the CLI, as comma-separated `metric=good:warn` pairs (e.g. `n50=2e6:5e5,seq_number=500:5000`; metrics: `busco_complete`, `busco_duplicated`, `n50`, `seq_number`). Previously, per-metric custom thresholds were only settable interactively in the Shiny app.

### `Fixed`

- Fixed BUSCO not showing in the tree
- Fixed the Shiny app launcher pulling its container from Docker Hub instead of quay.io (the plain `docker run` does not receive the `docker.registry` prefix), which caused a `pull access denied` error.
- Shiny app: the tree-style controls now show only the options that apply to the selected layout (margin/bar/pie controls for the non-circular styles, a ring-thickness control for the circular style), added a "Ring thickness" slider for the circular layout, and clarified the "Skip Statistics" labels.
- Circular layout: the "Tip Text Size" control now scales all text (tip numbers, ring legends and the species key), and the ring legends are ordered outer-ring-first to match the ring stack.
- Shiny app: the circular layout now offers a "Quality thresholds (phylo group)" preset selector plus a "Custom..." option exposing per-metric Good/Warn cut-offs (BUSCO complete, BUSCO duplicated, N50, sequence count), and a "Print values on rings" toggle.
- Circular layout: quality statistics (sequence count, N50, BUSCO complete for genome and protein, BUSCO duplicated) are now scored as a colour-vision-safe **traffic light** (Good/Warn/Poor) against phylogenetic-group thresholds (`--quality_preset`: generic, vertebrate, insect, plant, fungi, bacteria), rather than a sequential ramp that misleadingly implied "dark = good" (it was backwards for sequence count). Descriptive statistics (genome size, gene number, ortho seqs) are drawn in a neutral **grey** ramp and grouped as a separate outer block, so they never borrow the traffic-light colours or sit interleaved with the quality rings. `--show_ring_values` prints each value on its ring as a redundant, non-colour-only encoding. Both are also settable in the Shiny app.
- Circular layout: quality rings are now placed on the outer rim and descriptive rings nearest the tree, so the judgement-carrying rings read most clearly. The Good/Warn/Poor key is now drawn explicitly rather than relying on ggplot's legend, so all three swatches always appear, even when a ring happens to be a single grade throughout.
